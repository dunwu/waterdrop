1. 定位与边界

知识检索与引用解决：Agent 如何找到并使用知识？如何保证输出可信？

检索采用混合检索架构（Exact + BM25 + Vector），通过 RRF 融合 + Cross-Encoder Rerank 输出 Top-K 证据。引用由系统生成，模型只能使用检索到的证据 ID，幻觉引用率通过机制保证为 0。

2. 混合检索架构

3. RRF 融合

3.1 公式

RRF(d) = Σ_{r ∈ 检索通道} 1 / (k + rank_r(d))
  • rank_r(d)：文档 d 在通道 r 结果列表中的名次（从 1 开始），不是相似度分数
  • k：平滑常数，起始值取 60。依据：RRF 原论文（Cormack et al., 2009）取 k = 60；Azure AI Search 官方建议「set k to a small value, such as 60」；Elasticsearch rank_constant 默认亦为 60。注意 k = 60 是算法常数，不是某个产品的可调默认值。
  • 每通道先取 rank_window_size 条参与融合。初始值取 50–100，属本方案自拟起点而非业界默认：Elasticsearch 的 rank_window_size 默认等于请求的 size 参数（不是 100）；Azure AI Search 的语义重排默认只作用于 top 50。取值须按 Recall@K 与延迟预算实测校准（见 09 §2.7.2）。
  • 许可证前提：Elasticsearch 的原生 RRF 属 Relevance Engine 功能，需 Platinum/Enterprise 订阅（8.19 仍为付费）；若使用 Basic 许可，RRF 须在应用层自行实现。

3.2 关键约束

  • 去重键：chunk_hash。同一 chunk 被多通道召回时合并分数
  • 新鲜度校正：只作用于同一条知识的不同修订，不得跨知识比较时间
  • revoked 的修订一律不参与召回（已撤销 = 不可信）。
  • deprecated 的修订是否参与召回，04 与本文结论冲突且尚未裁决：04 §3 侧的表述是「可召回但必须带过期警告」，本文 §8 的表述是「只有过期版本 → 拒答」。二者不可同时成立，已登记为待决策项（本文 §14 RT3.1；原写「09 §6.2 L6」，但 09 §6.2 的 LD6 是「Embedding 模型选型评测是否提前到 P1」，与本议题无关，属错引）。在裁决前，实施按更严格的一侧执行（不参与召回），理由是放宽容易收紧难：一旦 Agent 已经依赖 deprecated 内容作答，再改为拒答会造成能力回退。

4. Cross-Encoder Rerank

部署方式候选数量级说明
本地 GPUTop 20-50延迟可控，推荐
本地 CPU（ONNX 量化）Top 20延迟随候选数线性增长
云 Rerank APITop 20需配熔断

先用融合分数截断到候选窗口，再 rerank，不能对全量召回结果 rerank。

5. 延迟预算分解

检索延迟 P95 ≤ 500ms 的分解：

环节预算超预算处置
查询理解（术语/别名扩展）查表实现，不调用 LLM若引入 LLM 改写，500ms 目标不再成立
三路并行召回取三路最大值，非求和单通道超时降级为双通道
RRF 融合内存计算，可忽略—
Cross-Encoder Rerank候选窗口按 §4 限定超时则跳过 rerank

关键约束：「查询理解不调用 LLM」是 500ms 目标成立的前提条件。

7.2 幻觉引用率 = 0 的机制保证

模型输出的每个 evidence_id 必须存在于本次检索返回的集合中，否则该 claim 整体丢弃并计入「幻觉引用」——该指标因此是机制保证而非模型自觉。

7.3 知识修订后的引用可解析性

当 section_anchor 在新版本中不存在时，按以下顺序降级解析：

  1. chunk_hash 精确匹配
  2. section_anchor 模糊匹配
  3. 回落到 knowledge_id 整条并标注「引用定位已降级」

8. 拒答与降级

情况行为
没有可靠证据拒答：「知识库中未找到相关信息」
只有过期版本拒答：「相关信息已过期，请联系 Owner 确认」
来源互相冲突降级：「存在多个版本的说法，以下是各方观点...」
权限判断失败拒答：「您没有权限查看相关信息」
来源完整性验证失败拒答
引用与当前版本不一致警告：「以下信息可能已过时」

9. 权限、安全与审计

9.1 权限模型：检索前过滤 + Chunk 级 ACL

三条硬性要求：

  1. 过滤发生在检索之前，不是之后
  2. Agent 代替人调用时，使用发起人的权限，不使用 Agent 自身的服务账号权限
  3. 权限集获取失败 = 拒答，不得回落为无过滤检索

10.2 知识分流判据

判据归属理由

11. 实施步骤

步骤顺序即实施顺序，不得按「先做有趣的、后做安全的」排列。原表把混合检索（09 评为 P2）放在 S1、把权限过滤（09 评为 P0）放在 S2，照此施工会先产出一个无权限过滤的检索服务——这正是 OWASP RAG 威胁清单中排名最前的失控场景，且一旦有 Agent 接入就产生真实越权暴露。下表已按蓝图优先级重排，并增加「优先级」列与 09 §3 的期次对齐。

分期结论：P0 交付的是「带权限过滤、带审计、可溯源、会拒答的 Exact + BM25 检索」，而不是「语义检索」。语义能力（向量 + rerank）在 P2 才引入——这与 09 §3.1/§3.3 的期次划分一致，也是「先可信、后聪明」的刻意取舍。
