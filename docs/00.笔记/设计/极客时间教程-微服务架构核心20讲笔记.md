# 《极客时间教程 - 微服务架构核心 20 讲》笔记

## 什么是微服务架构

**微服务六大特点**：

- 一组小的服务
- 独立的进程
- 独立部署
- 轻量级通信
- 基于业务能力
- **无集中式管理**：可用不同技术栈、不同存储

**微服务定义**：基于有界上下文的、松散耦合的、面向服务的架构。

## 架构师如何权衡微服务的利弊

> **架构之道在于权衡利弊**

**优点**：强模块化边界、可独立部署、技术多样性

**缺点**：分布式系统复杂性、最终一致性、运维复杂性、测试复杂性

## 康威法则和微服务给架构师怎样的启示

**康威法则**：设计系统的架构受制于产生这些设计的组织的沟通结构。

![](https://raw.githubusercontent.com/dunwu/images/master/archive/2022/06/c65d534683414edfa6ffed90bd729b0f.png)

**康威四大定律**：

1. 组织沟通方式会通过系统设计表达出来
2. 时间再多一件事也不可能完美，但总有时间做完一件事
3. 线型系统和线型组织架构间有潜在的异质同态特性
4. 大系统总是比小系统更倾向于分解

**核心思想**：**分而治之**

## 企业应该在什么时候开始考虑引入微服务

- **单体服务**适用于小团队；**微服务**适用于大团队
- **经验数据**：团队达到 **100 人**规模时可考虑微服务架构
- 微服务对平台基础设施要求较高，初期不一定能提高生产力

> **罗马不是一天建成的**：架构是演进的过程，不应一开始就设计得过于复杂。

## 什么样组织架构更适合微服务

![](https://raw.githubusercontent.com/dunwu/images/master/archive/2022/06/ba22669f8299412b88179f3350dd736f.png)

- **传统组织架构**：产品流程线性流转，反馈慢，沟通成本高
- **微服务组织架构**：跨职能团队（开发+产品+测试），每个团队支持自己的微服务，交付平台对外提供 API

![](https://raw.githubusercontent.com/dunwu/images/master/archive/2022/06/ccd9a014f2884a0ca4f0c83181ba8896.png)

> **DevOps 理念**：谁开发的，谁构建，谁支持。

## 如何理解阿里巴巴提出的微服务

**中台战略与微服务的关系**：

![](https://raw.githubusercontent.com/dunwu/images/master/archive/2026/02/6d487eba6a464921b10c2f060943fc84.png)

- **业务中台 + 技术中台** = 大中台，支撑业务前台
- 与微服务相关的层次：`PaaS`（平台即服务）和核心业务层
- `IaaS`：Infrastructure-as-a-Service（基础设施即服务）
- `PaaS`：Platform-as-a-Service（平台即服务）

## 如何给出一个清晰简洁的服务分层方式

![](https://raw.githubusercontent.com/dunwu/images/master/archive/2022/06/ca00d58d802d40728ebd7978d28921a5.png)

**SOA / 微服务分层**：

- **基础服务**：核心领域服务 / 中间层服务 / 公共服务
- **聚合服务**：对基础服务的聚合，满足业务需求，提供给外部调用

## 微服务总体技术架构体系是怎么设计的

![](https://raw.githubusercontent.com/dunwu/images/master/archive/2022/06/0a1b01f6de8f4079a208a7785b2756c5.png)

- **接入层**：接入外部流量，内部负载均衡
- **网关层**：反向路由、限流、安全、跨横切面功能
- **业务服务层**：聚合服务 + 基础服务
- **支撑服务**：公共性后台服务
- **平台服务**：管理系统
- **基础设施**：运维团队维护

> 与微服务相关的主要有：**网关层、业务服务层、支撑服务、平台服务**

## 微服务最经典的三种服务发现机制

消费者如何发现生产者，三种模式：

### 模式 1：DNS + LB

通过 DNS 访问负载均衡，LB 分发请求。

![](https://raw.githubusercontent.com/dunwu/images/master/archive/2022/06/3230c921816f4705ab668385e2f3052b.png)

### 模式 2：客户端注册中心

消费者内置 LB，生产者注册到注册中心并发送心跳，消费者定期拉取生产者信息。

![](https://raw.githubusercontent.com/dunwu/images/master/archive/2022/06/65c88aa38f4a44448e28c19d60ff3598.png)

### 模式 3：主机 LB + 注册中心

Consumer 主机上布置 LB，LB 定期同步注册中心信息。运维成本较高。

![](https://raw.githubusercontent.com/dunwu/images/master/archive/2022/06/1d9dc2afbb71450fa417fdb0f2a4a509.png)

## 微服务 API 服务网关（一）原理

**网关作用**：屏蔽服务内部逻辑，对外提供统一接口。

![](https://raw.githubusercontent.com/dunwu/images/master/archive/2022/06/ae5dd8f637bc411ca4ba914c08090a05.png)

**网关核心功能**：

- **反向代理**：外部请求换成内部调用
- **安全认证**：防刷、防爬虫
- **限流熔断**：处理突发流量
- **日志监控**：访问审计、流量监控

> 不要把过多业务逻辑写在网关中

![](https://raw.githubusercontent.com/dunwu/images/master/archive/2022/06/21ce8b0d2c4543268e5b65f60dda2901.png)

## 微服务的容错限流是如何工作的

**Netflix Hystrix**：提供熔断、隔离、限流、降级功能。

![](https://raw.githubusercontent.com/dunwu/images/master/archive/2022/06/96dd74df765f45328a0b449bbb4eb71d.png)

**工作流程**：

1. `Circuit Open` 判断是否熔断 → 是则执行 `getFallback()` 降级
2. `run()` 超时 → 执行降级
3. `run()` 失败 → 执行降级
4. 成功执行后通过 `Calculate Circuit Health` 计算是否需要熔断
