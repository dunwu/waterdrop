# 面试题库 20h/周 学习计划（五模块 · 滚动排期版）

> 范围：`JavaCore` / `Java框架` / `数据库` / `分布式` / `设计` 五个题库（已去除大数据）。
>
> 目标：全部 **三星及以上** 题目的掌握度达到 🟢——题库系统化深度学习，不以面试日期为锚。
>
> 投入：每周固定 **20 小时**。名义 **38 周（约 9 个月，760 小时）**，区间 32–44 周；**无外部期限**，以出口闸门而非日历为准，周数是滚动预测。
>
> 32 周（640h）是**乐观下界**：只在单题耗时下浮且运营负荷取低时成立，不作为承诺。下面所有周次编号都是**内容周**（内容的序号），阶段超期在阶段边界占用弹性周（§3、§9）。
>
> 判定口径（双闸门）：
> - **🔵 待固化** = 90 秒脱稿讲清「是什么 + 为什么 + 怎么做 + 一个坑/取舍」，且 **D7 抽测通过**
> - **🟢 掌握** = 上述标准 + **D30 抽测通过**（方案题另加「能答 2 层追问」）
> - **🟡** = 能背要点、追问即卡；**🔴** = 讲不出主线；**空白** = 未测

## 二、工时测算（20h/周 容量模型）

### 2.1 学习负荷

单题学习时数假设：3⭐ 0.75h、4⭐ 1.5h、5⭐ 2.5h（首学 + 费曼输出 + 制卡 + D1/D3 回收）。按知识单元合并系数 0.7：

```
(261×0.75 + 255×1.5 + 17×2.5) × 0.7
  = 620.75 × 0.7 ≈ 435h（约 373 个学习单元）
```

### 2.2 运营负荷（随周数发生，不随题数）

| 项 | 口径 | 工时 |
| :--- | :--- | ---: |
| 当周混排抽测 + 错题归因（D7 轮） | 2h × 31 学习周 | 62h |
| 周级到期复习（D15/D30/D60 批次） | 2h × 31 学习周 | 62h |
| 周 Check / AAR | 1h × 31 学习周 | 31h |
| **小计** | | **155h** |

> 双周 Act（8h）、月度审计（9h）从机动出，不重复计入运营；P0/P3/P4 周内的 Check 已含在该阶段工时里。

### 2.3 容量闭合

| 项 | 工时 |
| :--- | ---: |
| 学习负荷（2.1） | 435h |
| 运营负荷（2.2） | 155h |
| P0 5★ 闭环与建档 | 40h |
| P3 整合与模拟 | 40h |
| P4 巩固与终测 | 60h |
| 机动（Act 8h + 月度审计 9h + 缓冲 13h） | 30h |
| **合计** | **760h** |

- 每周 20h 拆三类：**学习性时段 14h**（学习节 12h + 画图/双编码 2h）、**运营 5h**（抽测 2h + 周级复习 2h + Check 1h）、**机动 1h**（双周 Act、月度审计与拖延缓冲均从此出）。
- 学习周数 = 435 ÷ 14 ≈ **31 周**；加 P0 2 + P3 2 + P4 3 = **38 周（760h ÷ 20h）**。
- **为什么不是 32 周**：435h 新学需要 14h/周 × 31 周；按 12h/周 排会少算 3 周的学习时间，同时漏计抽测、周级复习、Check、Act 约 155h。两处补齐后才是 760h / 38 周。

> 单题时数与合并系数仍是假设。W2 诊断后用 §9.1 的「学习性时段 ÷ 完成题数」替换：上浮 20% → 学习 37 周、总周数约 44；下浮 20% → 学习 25 周、总周数约 32。**任何情况下都不压缩复习与闸门来保周数。**

> **两种周号，别混用。**
>
> - **内容周**（W1–W32）：内容的序号，§3 逐周任务与 §8 勾选表都按它编号，不随顺延重排。
> - **名义日历周**（W1–W38）：在 20h/周 与全部内容都做完的前提下，日历上的预测位置。

>
> 阶段工时对账：435 学习 + 155 运营 = 590h 落在 P1/P2（400 + 190），固定项 P0/P3/P4 共 140h，机动 30h（含 Act 8h、月度审计 9h、缓冲 13h），合计 760h = 38 周 × 20h。
>
> 里程碑 M1–M7 按**阶段出口**判定，不绑定日历周；M2 之后的实际日期随 P1/P2 弹性平移。

周内配比随阶段变化，不要用一套模板跑全程。

### 工作日两个窗口怎么选

默认 **19:30–21:30**。下午段（14:30–16:30）是例外选项，不是每天重新挑一次的备选。

| 规则 | 说明 |
| :--- | :--- |
| **按周定，不按天定** | 周日 AAR 时一次性指定下周每个工作日走哪个窗口，填进 §8.1 周计划卡的「窗口」列；当天不临时改 |
| **默认晚段** | 只有当「14:30–16:30 确认不会被会议打断」时才切下午段。坐班日一律晚段 |
| **同一天不拆段** | 120 分钟的七环节必须连续完成，不允许下午 45min + 晚上 75min 拼成一节 |
| **18:30 决策截止** | 18:30 还没开始，默认走晚段，不再回头考虑下午段 |
| **设计题优先下午段** | 当天下午确定空闲时，把设计、架构、分布式一致性这类需要整块推理的内容放进去 |
| **周内混用不超 2 天** | 一周切换窗口超过 2 天，说明日程不可控——固化一个窗口，别每天决策 |

> 下午段的真实约束：**它只在 WFH、调休或弹性工时下成立**。如果必须坐班，这个选项就不存在。不要在计划里留一个每天都要重新判断的岔路，那是纯决策成本，不产生学习收益。
>
> 另外，14:30 正好落在午后低谷期。若连续两周的 Check 显示下午段的完成率或抽测通过率低于晚段，就放弃下午段——这是你自己的数据说了算，不是理论说了算。

> 晚段 21:30 收而不是 22:00，是刻意的：睡眠对记忆巩固的作用大于多学这 30 分钟。21:30 之后不再安排任何学习动作。

**为什么周三也是学习节（方案 C）**

旧排法把 60% 的负荷压在周六、周日（12h/20h），周中只有 4h。改成 5 个工作日各 2h 之后：**周中 10h、周末 10h，负荷对半**，周六的 6h 长块也降到 5h，单日峰值下降。

代价是**周一至周五连续 5 晚**，没有周中恢复日。三条对冲：

1. **周三设为轻量节**：只安排 3⭐ 题或速答卡，不排 5⭐ 与设计题。认知负荷最低的一天放在周正中间。
2. **允许周三缩到 90 分钟**：14:30–16:00 或 19:30–21:00，45min 精读 + 30min 费曼复述 + 15min 制卡，缺的 30min 用周六 11:00–12:00 的画图时段补（那一小时本来就是可让的）。
3. **周三缺席单独处理**：一次缺席不触发红线；连续两周缺席按 §9 规则 2 处理（题量减半），不硬撑。

> 负荷对比：旧排法周四—周日 16h（80%）；新排法工作日 10h（50%）、周末 10h（50%）。**削减的是单日峰值，不是总量**——学习节仍是每周 6 个（5 个工作日 + 周六 1 个），复习、抽测、归因、Check 各时段一小时未减。

**学习节 120 分钟结构**（周一至周五各一次；周三为轻量版，可缩到 90 分钟）：

| 环节 | 时长 | 说明 |
| :--- | ---: | :--- |
| 到期召回 | 10min | **按台账取 D1/D3 到期单元**，2min/个脱稿提取；无到期则白纸默写上节框架 |
| **盲答** | **8min** | 不查资料，写下已知关键词 + 猜一条主线；写不出就写"不知道"。记录盲答命中率，作为掌握度初值 |
| 精读 | 22min | **只补盲答暴露的缺口**，不线性通读；对照答案标三类：盲答命中 / 遗漏 / 讲错 |
| 费曼复述 | 20min | **合上材料**讲给“不懂的人”，录音；卡壳处标记回炉 |
| 白纸输出 | 20min | 写「是什么 / 为什么 / 怎么做 / 一个坑」四段 |
| 制卡 | 15min | 只把**事实类**（版本号、参数、状态机、命令）做成原子卡 |
| 当周小测 | 15min | 遮答案自测 3–5 题 |
| 记录 | 10min | 台账填首学周与 D1/D3/D7/D15/D30 到期日 |

> 「精读」和「费曼」是两个动作，不能合并。精读是输入，费曼是输出——只精读不复述，等于没学。

> **为什么盲答排在精读前面**：预测试效应——先尝试提取，哪怕答错，之后读答案的保持效果也优于直接阅读；同时它暴露真实缺口，把 30min 精读压到 22min。三个例外：
>
> - **完全零先验**（没做过、没听过）：先看 2 分钟答案的三级标题搭框架，合上，再闭卷复述。
> - **状态是 🟡 / 🔴 的旧题**：直接闭卷重建，不精读，只对照缺的要点。
> - **D7 / D30 到期复习**：纯提取，**绝不重读**。重读会制造流畅性错觉，把 🟡 伪装成 🔵。

### 时段保护规则（四象限的落地）

20 小时是**预占的 Q2 时段**，不是“有空就学”。冲突时按以下顺序让路，顺序不可颠倒：

| 优先级 | 时段 | 可否让路 |
| :--- | :--- | :--- |
| 1 | 日级 10min 到期召回 + 周日 2h 周级复习 | **不可让**。让掉一次，复习债立刻滚起来 |
| 2 | 周一至周五 学习节 | 最多让 1 次/周，且当周补回；**周三可缩到 90min** |
| 3 | 周六 1h 当周抽测 + 1h 归因 | 最多让 1 次/两周 |
| 4 | 周六 1h + 周日 1h 画图与预习 | 可让。这是最先牺牲的一块 |
| 5 | 周日 1h AAR + Check | 可缩短到 20min，不可跳过 |

- 连续两周有 ≥2 个时段被挤占 → 触发 §9 规则 2，周目标减半，**但时段本身不取消**。
- 不要用“这周太忙，下周补 40 小时”来还债。单周超过 24 小时的那一周，产出通常低于正常周。
- 周三虽可缩到 90min，但**不建议连续 3 周都缩**：一旦形成惯性，等于回到「4 个学习节」的旧排法，负荷重新压回周末。

### P0（W1–W2）：5★ 全量闭环 + 建档

P0 不是“只测不学”。每个单元走完整闭环，测完当场进入学习或巩固：

```
测（盲答） → 判定 + 要点反馈 → 学（🔴 / 🟡）或 固（🔵 / 🟢） → 台账 + D1
```

> 🔴 **铁律：一个时段只处理一个单元，测与学必须同日完成。**
>
> 测而不学，等于把成本付掉、把收益留到明天；而明天有明天的测与学，欠账会立刻滚起来。所以**不许批量测**——一次测 7 个，就必然要跨日补学，闭环就断了。
>
> 单时段装不下（比如 5★ 首学要 100min、工作日只有 120min）时，正确做法是**减少当天测的单元数**，不是把学习推到第二天。

改为闭环的三个理由：

1. **预测试必须配反馈才有收益。** 只测不学，等于付了尝试的时间，没拿到编码的效果。
2. **原计划 W3 学习节开头还有一次“盲答 8min”。** 同一单元被测两次、间隔两周，是纯重复劳动。
3. **原计划在 P0 同时诊断 188 道 4★ 空白。** 这些题在 P1 还要再学一遍，而诊断信息只有“会不会”，收益低于一次完整闭环。

所以 P0 只做 **5★ 的 17 个单元**。原 4★ 空白诊断取消——它们会在 P1 学习节的盲答里完成同样的测量，不再重复。

单单元基准：5★ 闭环约 **100min**（测 8 + 反馈 3 + 精读 22 + 复述 20 + 输出 20 + 制卡 15 + 记录 10 + 缓冲 2）。17 单元 ≈ 28h，加建档 / 清单 / 基线 12h = 40h，正好两周。

> P0 不适用「周三轻量节」：5★ 闭环是最重的认知任务，周三与其他工作日同量。
>
> 下表工作日只标星期：时段按「14:30–16:30 或 19:30–21:30」二选一。周末固定。

### 5.2 复习阶梯

| 轮次 | 时点 | 形式 | 通过标准 |
| :--- | :--- | :--- | :--- |
| 第 1 轮 | D1 | 遮答案自测 | 能说出 3 个关键词 |

> 🔴 **每一轮都是「测 + 补」，不是「测完记一笔走人」。** 未通过的单元，当场把缺的要点补上、再讲一遍，然后才记这一轮的 Dx。
>
> D1 / D3 / D7 / D15 / D30 是**遗忘曲线上的复习点**，不是「今天测、明天学」的排期表。把补学推到下一次，等于让遗忘曲线多跑一段——测完的当天不补，前面那次测就白测了。

- **W3–W12 首学的单元加 D60 轮**（跨度过长，必须多一次）；W20 之后首学的可省 D60。
- **载体分工**：D1/D3 由每个学习节开头的 10min「到期召回」承担（日级，每次 ≤5 个单元）；D7 由周六 2h 混排抽测承担；D15/D30/D60 由周日 2h 周级复习节承担（单次 60–90 个单元，约 2h，超出则顺延，不顺延超过 2 天）。日级到期超过 5 个时，用通勤 15min 时段补。
- 概念卡不进 Anki。Anki 只放事实卡（10–20 秒/张）；概念题走「问题 → 90 秒提纲 → 录音自评」——概念单元的 D1/D3 同样走口述提取，不因「不进 Anki」而缺席。

### 5.3 失败处理（leech 规则）

同一单元连续 **3 次**未通过 → **停卡**，退出复习队列，回炉费曼重讲（重走精读 → 复述 → 白纸输出），然后以 D1 重新入梯。

继续刷卡只会固化错误，不会改善。这是唯一允许“插队”的情况。

### 5.4 测后处置：学还是固

**测完必须给反馈。** 不给反馈的测验只产生焦虑，不产生记忆——这是预测试效应成立的前提。但反馈的深度按结果缩放，不是每题都从头学：

| 结果 | 处置 | 具体动作 | 时长 |
| :--- | :---: | :--- | ---: |
| 🔴 讲不出 / 不记得 | **学** | 3 条要点 + 1 个坑 → 精读 → 费曼复述 → 白纸输出 → 制卡 | ~80min |
| 🟡 部分命中 | **补** | 只给缺的那几条 + 1 个坑 → 复述 → 白纸输出 | ~30min |
| 🔵 可复述 | **固** | 3 条要点 + 1 个坑；不重学，只记 D1 | ~5min |
| 🟢 掌握 | **固** | 一句话确认 + 1 个坑；**反驳不出这个坑就降回 🟡** | ~3min |

两条纪律：

1. **反馈照给，深度按缺口缩放。** 完全掌握的题也要给要点——但要的是「这一题最容易错的地方」，不是再讲一遍定义。能指出坑，说明你真的懂；指不出坑，说明只是记住了。
2. **反馈必须在当天完成。** 隔天再补，预测试的收益已经衰减。这也是 P0 改成闭环的直接原因。

### 5.5 要点输出格式（学习 / 巩固环节）

每个单元的输出固定为下面这个结构，不省略任何一段：

```markdown
### 块 N · 单元ID 题目（🔴 学 / 🟡 补 / 🔵 固 / 🟢 固）

1. **机制名**：一句话讲清是什么、为什么这样设计。
2. **机制名**：……
3. **机制名**：……

> 【**陷阱**】触发条件 → 后果 → 正确做法。

> 【**答案**】[文件名 · L行号](绝对路径) → 「题目原文」
```

四条约束：

1. **恰好 3 条要点**，每条以加粗的机制名开头，不写定义堆砌。少于 3 条说明没吃透，多于 3 条说明没提炼。
2. **陷阱必须具体**：写清「什么条件下会踩、踩了会怎样、正确做法是什么」，不能只写“注意 XX”。
3. **答案链接用绝对路径**，方便直接打开；台账内仍用相对路径（随 vault 移动不失效）。
4. **行号会漂移**，只作大致定位；链接指向文件，进文件后按标题检索最稳。

> 本节只保留与**排期**相关的部分。完整流程（七步、检查点 CHECKPOINT-L1~L3、失败分支、反例）见 interview skill 的 `reference/learning-loop.md`（模式六：学固闭环）——那里是单次执行的唯一规约，本计划负责决定"什么时候做"。单次会话中的操作一律按该细则执行。

### 8.1 周计划卡（每周一张，复制使用）

勾选表记的是“这周做没做完”，周计划卡记的是“哪天做的、走的哪个窗口、为什么没做”。两张表分工不同，不要合并。

| 机动 | 任意 | 1h | | ☐ | |

> 合计 20h：学习节 12h + 画图 2h + 抽测归因 2h + 周级复习 2h + Check 1h + 机动 1h，与 §4 的类别口径一致。

填写时点：

| 时点 | 填什么 | 耗时 |
| :--- | :--- | ---: |
| 周日晚（AAR 时） | 「窗口」列全填好（晚 / 下），写清主攻与计划题量 | 2min |
| 每天结束后 | 实际时长、完成勾、备注 | 30s |
| 周日 Check 时 | 直接读卡算完成率，不靠回忆 | 1min |

三条约束：

1. **只记事实，不记感受。** 不写“今天状态不好”，写“加班到 21:40”。
2. **不做连续天数、不做累计、不设奖励。** 这张卡是归因工具，不是打卡表——一旦开始数连续天数，“不断签”就会取代“学扎实”成为目标。
3. **缺勤必须写原因。** 空着的备注等于没有数据。连续两周同一晚缺勤，才说明是排期问题。

这张卡同时补上两处缺口：§4 的窗口分配有了落点，§9.1 的完成率有了原始数据。

## 九、校准节奏：周 Check、双周 Act

PDCA 的两个动作分开跑：**Check 每周做，Act 双周做**。Check 采集事实，Act 改变量。合成一个动作，就会变成“每周都在改”，计划永远在震荡。

### 9.1 每周日 1 小时：数据化 Check

五项指标，**缺一项本周不进 Act**：

| # | 指标 | 怎么算 | 健康线 |
| :--- | :--- | :--- | :--- |
| 1 | 完成率 | 实际完成题量 ÷ 计划题量（数据来自 §8.1 周计划卡） | ≥80% |
| 2 | 中位单题耗时 | 本周**学习性时段**时长（学习节 + 画图输出）÷ 完成题量 | ≤ 假设值 ×1.2 |
| 3 | 到期复习完成率 | 完成单元 ÷ 到期单元 | ≥85% |
| 4 | 当周抽测通过率 | 通过题数 ÷ 抽测题数 | ≥80% |
| 5 | 旧题抽测通过率 | 通过题数 ÷ 抽测题数（W4 起） | ≥85% |

> 完成率必须用**题量口径**，不用“天数口径”。若某周只记了勾没记题量，可临时用「完成天数 ÷ 7」顶上，但两周内必须恢复题量口径——否则完成率会掩盖“每天做了但只做了一半题”的情况。

记录表（按周追加，只留最近 8 周，更早归档）：

| 周 | 计划 | 实际 | 完成率 | 单题耗时 | 到期复习 | 当周抽测 | 旧题抽测 | 判定 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | :--- |
| W3 | 17 | | | | | | — | |
| W4 | 17 | | | | | | | |
| W5 | 11 | | | | | | | |

判定三档：**达标**（5 项全达标）／**观察**（1 项不达标，下周继续盯）／**预警**（≥2 项不达标，或任一红线被触发）。

> 这三档刻意不用颜色词。🟡/🔴 已经被掌握度占用（追问即卡 / 讲不出主线），再用「黄/红」描述健康度，两套含义会在 Check 时打架。**掌握度看颜色，健康度看词。**

> 指标 2 是重算周数的唯一口径。用「学习性时段 ÷ 题数」而不是「总投入 ÷ 题数」：20h 里只有 14h 产生新学，用 20h 做分母会把每个单元算便宜 30%，周期必然低估。

### 9.2 每双周 30 分钟：只调一个变量

偶数周的周日，在 Check 之后追加 30 分钟 Act。从本周与上周的 Check 里挑**偏差最大的一项**，只改**一个变量**：

| 可选变量 | 具体动作举例 |
| :--- | :--- |
| 模块顺序 | 把「设计」整体前移到「分布式」之前 |
| 时数配比 | 周级复习 2h→3h，抽测 2h→1.5h，机动 1h→0（从机动借时间） |
| 单题时数基准 | 用实测中位数替换 3★ 0.75h / 4★ 1.5h / 5★ 2.5h，同步重算剩余周数 |
| 卡片粒度 | 一个单元拆成两个，或三题并成一单元 |

**不许动的**：🟢 判定标准、复习阶梯轮次、阶段出口判据（周数只能顺延，不能压缩复习与闸门）。

Act 记录表：

| 双周 | 触发指标 | 改的变量 | 改前 → 改后 | 验证指标 | 2 周后结果 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| W4 | 旧题抽测 70% | 时数配比 | 周级复习 2h→3h，抽测 2h→1.5h | 旧题抽测 ≥85% | |
| W6 | | | | | |

一次只改一个，是为了能归因。同时改两个，两周后不知道是哪个起了作用——这就是“计划震荡”的来源。

### 9.3 红线：不等双周，立即触发

| 指标 | 红线 | 立即动作 |
| :--- | :--- | :--- |
| 到期复习完成率 | <85% | 下周**暂停新学**，先清复习债 |
| 抽测通过率（当周或旧题） | <80% | 间隔 D30→D15，回炉费曼，不加新题 |
| 完成率 | 连续 2 周 <50% | 题量减半，保留时段 |
| 中位单题耗时 | > 假设值 1.5 倍 | 按比例重算总周数，周期顺延 |
| 同一单元失败 | ≥3 次 | leech：停卡回炉，D1 重入梯 |

红线动作**立即执行**，不等双周 Act。它们不是变量调整，是止损。

### 9.4 四种节奏的分工

| 频率 | 动作 | 时长 | 产出 |
| :--- | :--- | ---: | :--- |
| 每周日 | AAR 四问 + 数据化 Check | 1h | 五项指标 + 达标/观察/预警 |
| 每双周 | Act：改一个变量 | 30min | Act 记录表一行 |
| 每 4 个学习周末 | 题龄分桶审计（§6） | 1.5h | 7/30/90 天通过率 |
| 每阶段末 | 里程碑复核（M1–M7） | 1h | 是否进入下一阶段 |

月度审计不是周 Check 的替代：周 Check 看本周，月度审计看 90 天退化，结论进入下一个双周 Act。

### 9.5 规则清单

1. **五项指标缺一项，本周不进 Act。**
2. 完成率 <70% 连续两周：题量减半，保留学习节，周期顺延，**不压缩复习**。
3. 抽测保持率 <80%：间隔 D30→D15，回炉费曼重讲，下周不加新题。
4. 到期复习完成率 <85%：暂停新学一周，清复习债。
5. 真实单题耗时 > 假设 1.5 倍：重算总周数，优先调模块顺序，不降 🟢 标准。
6. **每双周只调一个变量**，改完给 2 周观察窗口再评估。
7. 组合本身是假设：连续一个月完成率与保持率同时不达标，换组合，不加方法。
8. 模拟频次是已知取舍：P3/P4 共 3 场全真模拟，不做双周模拟；若要做，从机动 30h 划，不碰复习与学习节。
9. **无外部期限**：周数只用于预测，不作验收。阶段都可以顺延；压缩只能压题量或范围，不能压复习轮次与 🟢 闸门。每双周 Act 用「学习性时段 ÷ 完成题数」重算剩余周数，写进台账。

## 十一、判定口径差异

- **设计 / 分布式方案题**：没有唯一答案。🟢 的标准是「框架完整 + 取舍有依据 + 能答 2 层追问」，不是背标准答案。这类题不进 Anki，只走口述 + 评分表。
- **JavaCore**：已完成全量评估，仅 32 个缺口，作为 W3 收尾，不占主攻时间；但已 🟢 的 111 题仍要按 D30/D60 抽检，防止退化。
- **已去除大数据**：原 49 题（含 9 道五星）不在本计划内；若后续转向数据平台，单独追加 3 周支线，不影响主线。
- **🟢 不是终身有效**：D60 复核失败即降回 🔵，重新入梯。掌握度是状态，不是勋章。

## 附录 A：AAR 四问（每周日 30 分钟）

1. **预期**：本周计划完成哪些单元、多少题？
2. **实际**：实际完成了多少？到期复习清了多少？抽测通过率多少？
3. **差异**：差在哪一环——容量（时间不够）、方法（学了记不住）、还是内容（题太难/无答案）？
4. **下一步**：下周**只改一个**动作，写具体（例：把费曼复述从 20min 提到 30min），不写“要更努力”。

## 附录 B：模拟面试评分表（P3 / P4 用）

每场 5 题，逐题打分，满分 25。

| 维度 | 1 分 | 3 分 | 5 分 |
| :--- | :--- | :--- | :--- |
| 正确性 | 结论错 | 结论对但有硬伤 | 结论对、边界清楚 |

## 附录 D：计划制定的方法论依据

这份计划不是"把常见学习法堆在一起"，而是按「定向 → 理解 → 记忆 → 应用 → 执行 → 校准」六个环节各配一个主方法，再用组合链串起来。下表逐项列出所用方法、证据等级、它解决的具体问题、在本计划中的落点，以及**它什么时候会失效**。

> 证据等级沿用方法论库的 S / A / B / C：**S** = 多项元分析或强一致证据；**A** = 多项研究支持；**B** = 有一定证据但边界明显；**C** = 启发式或个人经验，无实证最优值。等级表示证据强度，**不表示重要性**——C 级的番茄钟在该用的时候照样用，只是不能拿它当计划骨架。

### D.2 组合链：每个环节的主方法与产出

| 环节 | 主方法 | 补强方法 | 产出物 | 验证指标 |
| :--- | :--- | :--- | :--- | :--- |
| 定向 | 容量闭合估算 + 滚动式规划 | 二八原则、事前验尸 | §2 工时表、§3 排期与弹性周 | W2 实测单题耗时替换后，总周数闭合 |
| 理解 | 费曼学习法 | 双编码、认知负荷控制 | 口述录音、架构图 / 时序图 | 90 秒内讲完四段且不断片 |
| 记忆 | 间隔重复 + 主动回忆 | 组块化、延迟验收 | §5.1 台账、每日到期清单 | 到期复习完成率 ≥85%、D30 通过率 ≥80% |
| 应用 | 交错练习 | 刻意练习、反馈 | 混排抽测、附录 B 评分表 | 旧题抽测 ≥85%、模拟 ≥20/25 |

> **组合本身是假设，不是结论。** 方法之间的协同没有直接实验证据，只有各方法单独的证据。所以 §9.5 规则 7 写死了一条：连续一个月「完成率」和「保持率」同时不达标，就换组合，而不是继续叠加新方法。叠加是应对焦虑的本能，不是应对失效的策略。

## 附录 E：与 interview skill 的配套使用

`skillbox/skills/interview` 提供五项能力：模拟面试（深度 / 快速）、答案编写、索引维护、Anki 导出、重要度评估。它们与本计划是互补关系——**skill 测"能不能答"，计划管"能保持多久"**。

### E.1 计划环节 → skill 能力映射

| 计划环节 | 调用能力 | 具体动作 | 产物回写 |
| :--- | :--- | :--- | :--- |
| W1–W2 5★ 闭环（17 单元） | 快速评测 | 单元内一对一判定 + 精简参考（3 条要点 + 1 个坑），不展开全文 | 掌握度列 + 台账 |
| 每个学习单元（全周期） | 学固闭环（模式六） | 测 → 判定 → 学/补/固 → 3 条要点 + 陷阱 + 原文链接 → 复述 → 记账 | 掌握度列 + 台账 D1/D3 |
| P1 学习节（答案太薄 / 缺失） | 答案编写 | 按模板补全：💎 关键结论 → ⚡ 记忆卡片 → 📖 核心知识 → 🔬 扩展 → 🏭 实战 | 源文档 |
| 每周混排抽测（15–25 题） | 快速评测 | 5 题/批，完整五段输出；一次只推进一个板块 | 掌握度 + 评估列 |
| 周六错题归因 | 深度评测的 L1–L4 | 把"错在哪"从模糊的"子技能"落地为具体 L 级 + 维度名 | 评估列（L?） |
| P3 / P4 全真模拟（3 场） | 深度评测 | 8 维度、逐层追问 Level 1–5、陷阱追问、评估报告 | 评估列 + 附录 B 评分表 |
| 事实卡 | Anki 导出 | 把 🟡 / 🔴 导出为 CSV | AnkiDroid 牌组 |
| 已知重复题清理 | 答案编写（去重规约） | HTTP 缓存、MQ 三不、分布式锁、网关、链路追踪等 | 源文档 + 索引 |
| 阶段末索引核对 | 索引维护 | `bank_index.py audit` → 修差异 → `stats` / `render` | 索引统计块 |
| 星级复核（阶段末抽样） | 重要度评估 | 五维加权 + R1–R7，检查星级通胀与梯度倒挂 | 重要度列 |

### E.2 状态映射（最关键的一条）

skill 只有三态（✅ / ⚠️ / ❌），本计划有四态（🟢 / 🔵 / 🟡 / 🔴）。**不能一对一翻译**：

| skill 判定 | 写入本计划 | 理由 |
| :--- | :---: | :--- |
| ✅ 要点大部分命中 | **🔵 待固化** | 一次命中只是 D7 级证据，D30 尚未验证 |
| ⚠️ 部分命中 | **🟡** | 等价于"能背要点、追问即卡" |
| ❌ 基本未命中 | **🔴** | 等价于"讲不出主线" |
| 空白（未测） | 空白 | — |
| — | **🟢 掌握** | **评测永远不能直接授予**；只由台账 D30 / D60 复核写入 |

> **红线：评测只写 🔵 / 🟡 / 🔴，绝不写 🟢。** 评测是"当下能不能答"，🟢 是"30 天后还能不能答"。把评测的 ✅ 直接翻成 🟢，等于绕过双闸门——这正是本计划花 60h 建 P4 巩固期要防的事。

### E.3 每次调用的最小协议

1. **抽测**：一次只推进一个板块（skill 的板块顺序规则），批大小 5，测完立即回写，不跨模块开新批。
2. **诊断**：测完立即给**精简参考**——3 条要点 + 1 个坑，不展开「核心知识」全文。既保证反馈闭环，又不让输出量翻倍。不适用「关闭参考」——那样预测试拿不到收益。
3. **模拟**：深度评测只在 P3 / P4 开，P1 期间不消耗在完整 8 维度面试上——单场约 1.5–2 小时，加上复盘等于一个学习节，放进 P1 会挤掉新学时间。
4. **覆盖顺序**：评估列已有 L1–L4 的行，快速评测**不得覆盖**，只更新掌握度列。深度评测评级优先。
5. **检查点**：skill 的 CHECKPOINT-B（删题）、CHECKPOINT-C（导出 Anki）、CHECKPOINT-D（改星级）都要停下来确认；本计划只在阶段末触发这些动作，不在日常学习节里做。
6. **题面格式**：所有出题一律用 `**【难度】【星级】题目原文**`（中文星级，不带分类与掌握度），编号单独成行 `**题 N**`。题库源文件的答案标题 `### 【简单】…` 不动——Anki 导出脚本按固定正则解析，改了会破坏标题匹配。

### E.4 四处已确认的冲突与处置

| 冲突 | 证据 | 处置 |

### E.5 两边的能力边界

| | interview skill | 本计划 |
| :--- | :--- | :--- |
| 提供 | 分级诊断（L1–L4）、追问协议、反模式检测、答案生产、Anki 导出、星级标尺 | 长期保持（D1–D60）、双闸门、复习预算、周 Check / 双周 Act |
